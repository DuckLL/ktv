# 瀏覽器回歸測試

需要已完成 `uv sync`、FFmpeg、Node.js 及 Playwright Chromium。

```bash
npm install --prefix .venv/browser-tools playwright
node .venv/browser-tools/node_modules/playwright/cli.js install chromium
NODE_PATH="$PWD/.venv/browser-tools/node_modules" node tests/browser/practice.cjs
```

測試工具安裝在磁碟上的虛擬環境目錄。部分環境的 `/tmp` 是記憶體檔案系統，將瀏覽器或 FFmpeg 安裝在其中會佔用人聲分離所需的記憶體。

測試自動建立暫存歌曲與資料庫，啟動本機測試服務，完成後清除。歌曲目錄與資料庫皆在獨立的系統暫存目錄中，歌曲清理在匯入模組前關閉，不操作開發環境的歌曲資料。麥克風以已知的 A4 WAV 經 Chromium 收音流程輸入，會檢查音高辨識及接近目標的回饋。

影片走實際的原生控制快取流程。測試透過 Chromium 原生控制拖動音量、切換靜音，直接檢查伴唱／原唱兩個 Web Audio 增益；包含靜音中更改混音與 key、解除靜音、設定與鍵盤音量雙向同步。另模擬媒體音量唯讀，確認播放分頁音量在靜音／解除靜音後仍保留。

外部 YouTube／LRCLIB 回應以固定資料取代；音訊播放、音高分析、歌詞選擇與時間差保存使用實際後端。包含 ±0.2 秒與 ±0.5 秒按鈕、鍵盤前後調整 0.5 秒、混合步幅跨過零點、重置、重新載入後還原，以及延遲回應時切換歌詞版本、在等待新版本時調整舊版本時間差、快速分別調整兩個版本時間差的情境。瀏覽器例外會使測試失敗，另檢查 390／320 px 排版與設定還原。

以固定的人聲起音資料及舊的自動校正開啟偏好，驗證播放器不會自行更動或保存時間差；手動微調 0.2 秒後會保存，重新載入保持手動結果。介面的 ±0.2 秒、±0.5 秒與重置在 1366／800／768／390／320 px 均須維持同列。

響應式播放流程驗證 MV → 完整歌詞 → 音高圖的順序，320×568 的 MV 使用影片原始比例。桌機與手機皆使用原生影片播放與進度控制，時間差在外層同列調整，上／下一句為歌詞兩側的長按鈕。桌機聲音設定放在影片右邊，伴唱、混音滑桿、原唱在各種寬度都須維持同一行，且滑桿保留可操作的寬度。包含分頁鍵盤操作與 Escape 焦點還原、設定開啟時繼續播放、收起／展開 MV 後仍可播放暫停及操作原生時間條、進度跳轉與逐句跳轉、音高圖開關，以及全螢幕原生影片控制。

手機混音列固定在主畫面，實際操作原唱、35% 混音與伴唱，並檢查每種寬度維持單行。所有手機尺寸的升降 key 固定在播放分頁，並實際完成 +1／原調切換。430×932、390×844 的音高繪圖區須至少 110 px，同時保留至少 180 px 的歌詞區；390×700、320×568 保留歌詞空間。另檢查 844×390、568×320 橫向及收起 MV 的空間、桌機切回後控制位置及單一 DOM 節點。

歌詞檢查完整列表皆可顯示與捲動、目前句粉色高亮，以及跟隨時僅捲動歌詞容器。清除記憶涵蓋沒有同步歌詞的錯誤版本、取消延遲時間差保存、與尚在傳送的版本保存依序完成、重新整理維持已清除狀態，以及刪除失敗後保留原版本並可重試。

測試影片刻意使用 4:3，確認手機以來源比例滿寬顯示，影片上只有原生控制，YouTube 位於頂列，MV 開關在「播放」分頁。桌機與手機皆不顯示額外的全螢幕按鈕，並實際點擊原生影片控制驗證全螢幕進出。

寬螢幕另檢查聲音設定在 MV 右側、1366×900 時影片高度約 396 px、原生播放／暫停與左右逐句跳轉，以及收起 MV 後保留精簡原生播放器。

截圖預設存到 `/tmp/ktv-browser-review`；可用 `KTV_BROWSER_ARTIFACTS` 指定位置。自訂 Python 執行檔可設 `KTV_TEST_PYTHON`，連接埠可設 `KTV_TEST_PORT`。Linux 測試機需要 Chromium 使用的系統函式庫及中文字型。
